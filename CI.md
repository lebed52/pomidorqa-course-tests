# Как устроен CI проекта

При каждом Pull Request в `main` GitHub Actions поднимает чистую Linux-машину, устанавливает
зависимости, запускает линтер и все Playwright-тесты. Сам workflow лежит в
`.github/workflows/playwright.yml`; назначение настроек объяснено комментариями прямо в файле.

## Почему в `package.json` появились эти строки

Формат JSON не поддерживает комментарии, поэтому пояснения нельзя безопасно записать рядом со
строками: после этого `npm` перестанет читать файл.

```json
"lint": "eslint tests"
```

Команда `npm run lint` проверяет каталог `tests`. Одну и ту же короткую команду можно использовать
локально и в GitHub Actions — логика проверки не дублируется в workflow.

```json
"eslint": "^10.8.1"
```

Движок линтера: читает `eslint.config.mjs`, находит подходящие файлы и запускает правила.

```json
"eslint-plugin-playwright": "^2.11.0"
```

Добавляет правила для Playwright-тестов: например, находит `test.only`, `page.pause()` и забытый
`await`.

```json
"typescript-eslint": "^8.67.0"
```

Даёт ESLint парсер TypeScript, чтобы анализировать `.ts`-файлы без предварительной компиляции.

## Зачем коммитить `package-lock.json`

`package.json` допускает диапазоны версий, например `^10.8.1`. `package-lock.json` фиксирует точные
версии всего дерева зависимостей, включая вложенные пакеты. Поэтому локально и в CI устанавливается
одно и то же окружение.

Lock-файл генерирует npm — его не редактируют и не комментируют вручную. В репозитории он нужен,
потому что workflow использует `npm ci`: команда читает lock-файл и падает, если он не соответствует
`package.json`.

`node_modules`, напротив, в Git не добавляем. На каждой чистой машине CI зависимости заново
восстанавливаются командой `npm ci`.

## Чем CI-режим Playwright отличается от локального

Комментарии к этим строкам находятся прямо в `playwright.config.ts`:

- один повтор помогает увидеть признак нестабильного теста, но не лечит флак;
- один worker уменьшает гонки за общие данные учебного стенда;
- HTML-отчёт сохраняется как artifact, но не пытается открыть окно на headless-runner.

Локально Playwright не делает автоматический retry, сам выбирает число workers и открывает
HTML-отчёт после падения.
