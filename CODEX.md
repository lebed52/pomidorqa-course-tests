# Кодекс автотестов

Открыл этот файл и чужой PR. Больше ничего не нужно.

Комментарий пиши так: `кодекс 3, нет test.step` — не «тут плохо».

---

## 1. Где что лежит

```
tests/e2e/        сценарий: кто, что делает, что должно быть
tests/helpers/    данные и вход: makeUser, registerUser
tests/pages/      экран: локаторы и клики
```

В spec — кейс. В хелпере — пользователь. В странице — «сохрани имя».

Не клади `registerUser` в `ProfilePage` или `BookingPage`.  
Не клади `getByLabel` в spec, если страница уже есть.

---

## 2. Как выносить

Повторилось два раза — выноси.

| Живёт в | Что туда |
|---|---|
| `helpers/user.ts` | тип, фабрика, регистрация, логин |
| `pages/profile-page.ts` | `goto`, `saveName`, `addSkill`, поля формы |
| `pages/booking-page.ts` | каталог, календарь, модалка брони |
| spec | `beforeEach`, вызовы методов, `expect` |

Имя метода — смысл, не клик: `saveName`, не `clickSaveButton`.

`expect` из страницы не тащи. Страница кликает, тест проверяет.

Исключение: `registerUser` может закрыть вход через `toHaveURL`.

---

## 3. Каркас файла

```
test.describe("Профиль")                    // страница / фича
  test.beforeEach → свой пользователь + открыть страницу
  test("имя сохраняется после перезагрузки") // что проверяем
    test.step("сохраняем имя")               // действие
    test.step("после reload имя с сервера")  // проверка
```

Один `describe` — одна фича. Не складывай профиль и бронь в один файл «на всякий случай».

---

## 4. Степы

Каждый осмысленный шаг и проверку автотеста делаем через `test.step` с человеческим именем.

В степе-действии только то, что умеет Playwright: открыть, нажать, ввести, выбрать, обновить.

В степе-проверке только `expect`. Никаких кликов.

Первый шаг кейса — открыть страницу. Если `goto` уже в `beforeEach`, тест сразу про смысл — так тоже ок.

---

## 5. Имена

`Страница / фича → что проверяем`

✅ `test("имя сохраняется после перезагрузки")`  
❌ `test("тест 1")`  
❌ `test("fill input")`

Не думай каждый раз заново. Открыл соседний тест — скопировал каркас.

---

## 6. Один тест или два

Связанные проверки после одного действия — один тест. Имя, telegram и био за одно «Сохранить» — ок.

Если чтобы проверить второе надо заново регистрироваться и повторить половину шагов — режь на два теста.

Не плоди «проверить кнопку», «проверить текст», «проверить иконку». Suite раздуется, профита мало.

## 9. Ждать и проверять

Нет `waitForTimeout`. Нет `{ force: true }`. Нет `.only` и `page.pause()`.

`fill("Новое имя")` и сразу `toHaveValue` — проверка самого fill. Имя с сервера видно после reload. До reload дождись POST.

В проверке — уже случившееся: «форма открыта», не «должна открыться».
