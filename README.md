# PomidorQA — тесты марафона «Автоматизация на Playwright + TypeScript»

Официальный репозиторий марафона. Здесь живут эталонные автотесты на продукт
[PomidorQA](https://aiqa.su/pomidorqa) — сервис коротких встреч для QA/IT-специалистов, единственный
сквозной проект курса.

Продукт студентам доступен только как живой сайт (`aiqa.su/pomidorqa`) — исходный код самого
приложения закрыт (это часть приватного монорепозитория основного проекта AIQA). Здесь — только
автотесты и вспомогательный код для тестов.

## Зачем этот репозиторий

- **Читать эталонные тесты** — начиная с Урока 3 разбираем конструкции JS/TS прямо на этом коде
- **Клонировать и запускать** — начиная с Урока 5, когда в курсе появляется Git
- **Присылать pull request'ы** — начиная с Урока 5 (первый реальный PR с оптимизацией теста) и
  особенно с Урока 16 (полный путь тикет → тест → PR → зелёный CI)
- Репозиторий будет расти вместе с курсом: новые тесты, паттерны (POM/Component Object/Screenplay),
  CI-workflow (Урок 12) — всё сюда

## Хочешь прислать Pull Request?

## Запуск тестов

```bash
npm run test:unit   # Unit — без сети и без браузера
npm run test:api    # API — HTTP-запросы к локальному мок-серверу и служебной ручке стенда
npm run test:e2e    # E2E — реальный браузер на живом aiqa.su/pomidorqa
npm test            # все три уровня сразу
npm run report      # открыть HTML-отчёт последнего прогона
```

## Quality gate

Один вход для всех проверок — в том же порядке, в котором их запускает CI: от самой дешёвой
к самой дорогой.

```bash
npm run gate        # typecheck → lint → unit → api → e2e
npm run metrics     # сводка по JSON-отчёту последнего прогона
```

`npm run typecheck` ловит обращение к несуществующему методу Page Object до запуска браузера,
`npm run lint` — правила стабильности из `eslint.config.mjs`. Если падает статика, браузер
не поднимается: в GitHub Actions это отдельная работа `Typecheck and lint`, от которой
зависит работа с тестами.

`npm run metrics` читает `playwright-report/results.json` и показывает не только pass/fail:
распределение по уровням пирамиды, время прогона, самые медленные сценарии, повторы,
ожидаемые падения по известным дефектам и дисциплину набора — сколько E2E-файлов готовят
данные через API и сколько гарантируют cleanup.

## Покрытие требований

Покрытие считаем от функциональных требований MVP, а не от числа файлов: продукт тестируется
как чёрный ящик, его исходников здесь нет и code coverage измерять нечем.

[docs/coverage-matrix.md](./docs/coverage-matrix.md) — матрица «требование → статус → тесты».
У каждого требования один из статусов `automated`, `partial`, `known defect` или `out of scope`.

Расхождения требований и продукта не прячем: тесты на них лежат в
`tests/e2e/known-defects.spec.ts`, написаны по требованию и помечены `test.fail()`. Пока дефект
жив, прогон зелёный; когда продукт починят, Playwright сообщит «expected to fail, but passed».
Два расхождения из трёх после аудита уже исправлены в продукте, и тесты на них переехали
в обычные — `tests/e2e/slot-timezone.spec.ts` и `tests/e2e/cancel-window.spec.ts`.

По умолчанию E2E-тесты бьют в продакшен (`https://aiqa.su`). Если нужно направить на локальный
стенд — переопредели `POMIDORQA_BASE_URL`:

```bash
POMIDORQA_BASE_URL=http://localhost:3000 npx playwright test --project=e2e
```

## Структура

```
src/pyramid/       — вспомогательный код: чистые функции (unit) и локальный мок-сервер (api)
tests/unit/        — пересечение слотов по времени, форматирование времени, валидация пароля
tests/api/         — бронирование и гонка за слот на мок-сервере, регистрация на живом стенде
tests/e2e/         — пользовательские сценарии в браузере: регистрация, профиль, навыки,
                     слоты, каталог, бронирование, отмена, часовые пояса, окно отмены,
                     гостевой доступ, известные дефекты
tests/helpers/     — тестовые данные, регистрация через API, время слотов в поясе профиля
                     и гарантированный cleanup
tests/pages/       — Page Object на каждый экран: локаторы и действия
scripts/           — сводка метрик и AI-ревью Pull Request
docs/              — матрица покрытия и устройство AI-reviewer
```

**Домашнее задание:** открыть `tests/e2e/booking-flow.spec.ts`, прочитать каждую строчку и
написать построчно своими словами, что делает автотест. Решение — в чат марафона.
Запускать тест не обязательно. Подробности — в описании эфира и закрепе чата.
