# Как прислать Pull Request (Урок 5 и далее)

Этот репозиторий — общий для всех участников марафона. Чтобы прислать своё изменение, нужен
Pull Request. Ниже — шаги от установки до открытого PR.

## 0. Доступ

PR можно открыть только из ветки **этого же репозитория** (не форка) — так проще для первого
знакомства с Git. Для этого нужно быть приглашённым как collaborator:

1. Напишите свой GitHub-username в чат марафона в ответ на закреп Урока 5.
2. Куратор пришлёт вам приглашение (GitHub → уведомление / письмо на почту).
3. Примите приглашение — после этого можно клонировать репозиторий и пушить свои ветки.

Ветка `main` защищена — прямой push в неё невозможен ни у кого, включая куратора. Единственный
путь внести изменение — через Pull Request.

## 1. Клонирование и установка

Если клонируете впервые:

```bash
git clone git@github.com:lebed52/pomidorqa-course-tests.git
cd pomidorqa-course-tests
npm install
npx playwright install chromium
```

**Если репозиторий уже был склонирован раньше** (например, для чтения тестов на Уроке 3) —
не клонируйте заново, а обновите свою копию:

```bash
git checkout main
git pull origin main
```

`main` мог обновиться после вашего клонирования (например, в него доехал новый эталонный тест) —
без `git pull` вы будете работать со старой версией файла и рискуете чинить то, чего уже нет.

## 2. Запустите тесты — должны быть зелёными

```bash
npm test
```

Если что-то красное — разберитесь до того, как начнёте менять код (иначе не поймёте, ваша это
правка или существовавшая проблема).

## 3. Создайте свою ветку

Имя ветки — `hw5-<ваш-github-username>` (или `hw<N>-<username>` для следующих уроков), например:

```bash
git checkout -b hw5-shurigin-dmitriy
```

Так куратору легко находить и сортировать ветки/PR по автору.

## 4. Внесите изменение

Делайте только то, что просит домашнее задание конкретного урока. Не переписывайте чужой код
«по пути» — если увидели что-то кривое не по теме ДЗ, напишите об этом в PR отдельным комментарием,
но не трогайте.

**Урок 5:** в `tests/e2e/booking-flow.spec.ts` регистрация `guest2` всё ещё инлайн — замените её
на `registerUser(guest2Page, guest2)`, как уже сделано для host и guest. Остальные шаги гостя 2
не трогайте.

## 5. Закоммитьте и запушьте

```bash
git add -A
git commit -m "hw5: guest2 через registerUser"
git push origin hw5-<ваш-github-username>
```

## 6. Откройте Pull Request

На github.com откройте PR из своей ветки в `main` этого репозитория. GitHub подставит шаблон
из `.github/pull_request_template.md` — заполните все пункты.

## Что будет с вашим PR

Цель ДЗ — пройти процесс (ветка → коммит → push → Pull Request), как в реальной команде.
**Мерж в `main` и личное ревью каждого PR не обещаем**: десятки участников правят один и тот же
файл, после первого мержа у остальных конфликты, а поштучные комментарии на весь поток нереалистичны.

На эфире разбираем, **как в работе смотрят коммит и делают код-ревью** (diff, комментарий к строке).
Типичные решения и частые ошибки — выборочно на следующем эфире. Не мерж — это нормально и ожидаемо:
важно открыть PR, а не «попасть в main».

## Именование коммитов (по умолчанию, ужесточается на Уроке 16)

`hw<N>: короткое описание на русском` — например `hw5: guest2 через registerUser`.
